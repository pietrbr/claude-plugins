---
description: Summarize the session in a short report. Say what was done and what is still open.
---

Give the user a short report here in chat on where the session work landed.
Include the open items for the whole work session, not just since the last
summary. Keep it short, so the user can paste it to update a colleague.

Explain it as you explain it to a colleague with little to no context. The
colleague did not see this conversation. Name what things are (the repo, the
file, the bug, the tool) instead of using labels or shorthand that only make
sense inside the chat. Say what was done, why it matters, and what is left.

Chat only: do NOT read or write files, run tools, or commit. Base the summary
solely on the conversation so far.

The goal is a summary the user is happy to send as is. If the user asks for a
shape, a length, or a focus, follow that over everything below.

User request: $ARGUMENTS

Make it schematic: bullets, one point per bullet, no paragraphs. Each bullet
is a full sentence that tells part of the story, for example "X was a
problem, so we did Y". A reader must follow the thread from bullet to bullet.

Start with the original problem, as the user first framed it. If the scope
drifted, say so in its own bullet: what the work became and why.

Group the bullets under short section labels. If they help, use some of
these sections:

- Status: one line on where things stand now.
- Problem: the original ask.
- A topic name: what was done on that topic.
- Decisions: the choices that shaped the result, with the rejected options
  and why they lost.
- Open items: what is still to do, unresolved, or waiting on someone.
- Next step: the single action to resume on.

Size it to the work, not to a template.
A small change can take two or three sections with one bullet each. A large
or multi-topic session can take more sections and more bullets. Do not add
bullets or sections to fill a shape. If there are open items, they always
get their own section, because the reader acts on them.

Guidelines:

- Cover every topic of the session, but cut routine back-and-forth and minor
  mechanics.
- Keep each bullet to one or two lines.
- Name things so that someone outside the session understands each bullet.
- Skip empty parts instead of writing "none".
